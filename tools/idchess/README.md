# Разбор записей idChess

Инструменты, чтобы проверять и настраивать распознавание на настоящих записях idChess. Ролик idChess имеет размер 720×1200: сверху (720×480) снята доска, снизу (720×720) idChess рисует свою цифровую доску. Цифровая доска служит «правильными ответами»: по ней известно, где стоят фигуры в каждый момент.

Нужны Python 3 с numpy и Pillow, ffmpeg, Node.js и `npm i chess.js@0.12.0`.

1. **Позиции с цифровой доски.**
   ```
   python3 gt.py tpl.png video.mp4 gt.json 10
   ```
   `tpl.png` — кадр любого ролика idChess с начальной позицией, из него вырезаются шаблоны фигур. На выходе — список `{t, placement}`, по записи на каждое изменение позиции.
2. **Ходы.**
   ```
   node gt_moves.js gt.json moves.json
   ```
   Восстанавливает ходы (до двух полуходов между соседними позициями) и стартовую позицию в FEN.
3. **Углы доски на съёмке.**
   ```
   python3 corners.py video.mp4 gt.json x1,y1,x2,y2,x3,y3,x4,y4 corners.json
   ```
   На вход — грубые углы в пикселях кадра 720×480, в любом порядке. Скрипт уточняет их по контрасту границ между пустыми клетками и находит ориентацию `k`.
4. **Сигналы клеток офлайн.**
   ```
   DATA=… node offline.js rN t0 t1 e2 e4
   ```
   Прогоняет `js/board-vision.js` по кадрам. В `DATA/site/test/rN.webm` должна лежать съёмка (только верхние 720×480), рядом `rN.json` с полями `{corners, k}`.

Что показали первые 5 роликов (тур 4, столы 16/3/1/9 и др.):

* Камера стоит над доской, поэтому фигуры на снимке «наклоняются» от центра кадра, а не вверх. Это учитывает модель камеры (`cameraFromH`).
* Видео сжато, а дети почти всё время в кадре, поэтому порог движения у каждой клетки подстраивается под её собственный шум.
* Чёрная фигура на тёмной клетке и белая на светлой меняют картинку слабо. Это главный источник пропусков.
* Ролики начинаются посреди партии, часто с рукой над доской. Для честной проверки исходный вид доски нужно брать с чистого кадра.
